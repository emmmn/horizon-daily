### [OpenAI 发布 GPT-6 Astra，性能强劲且定价对标 Claude](https://simonwillison.net/2026/Sep/3/gpt6-astra/) ⭐️ 9.0/10

OpenAI 于 2026 年 9 月 3 日发布 GPT-6 Astra，该模型即日起向有限组织开放，并将在未来几天内向所有 ChatGPT Plus、Pro、Business 和 Enterprise 用户以及通过 OpenAI API 和 AWS 提供。其 API 定价与 Claude Fable 5 和 5.1 相同：每百万输入 token 10 美元，每百万输出 token 50 美元。在 ARC-AGI 3 基准测试中，Astra 使用 OpenAI 自定义的 Provider Adapter harness 取得了 99.9%的分数，而默认 harness 仅得 62.7%。此外，Astra 在安全任务上表现突出，在 ExploitBench 上得分 100%，在 ExploitGym 上得分 42.4%，并在 SRE-Bench 二进制逆向工程中四次尝试内达到 99.2%。在长上下文处理方面，Astra 在 256K-512K token 范围内达到 100%准确率，在 512K-1M token 范围内达到 96.3%。然而，在 Artificial Analysis 的 Intelligence Index 上，Astra 得分 61，低于 Claude Fable 5.1 的 66（含回退），但它在 Coding Agent Index 上以更低成本领先。API 模型标签为 gpt-6-astra。

**「背景」** GPT-6 Astra 是 OpenAI 于 2026 年 9 月发布的新一代旗舰模型，被官方称为“最智能且最对齐的模型”，旨在升级 ChatGPT 和 Codex 的能力。该模型在计算机使用、编码、网络安全和科学任务上具备先进性能，并被视为 OpenAI 对 Claude Fable 5 等竞品的直接回应。ARC-AGI 3 是一个于 2026 年 3 月发布的抽象推理基准测试，用于评估模型的通用智能水平，而 OpenAI 的“Provider Adapter harness”是一种自定义测试框架，通过保留请求间的推理状态来提升模型在长对话中的表现。

**「影响」** GPT-6 Astra 的发布将直接影响 AI 编码和智能体开发领域，其定价与 Claude Fable 5 持平，但在多个基准上表现更优，可能促使开发者和企业重新评估模型选择，尤其是在成本敏感的场景下，Astra 可能成为更具吸引力的选项。

Anthropic 发布了 Claude Code v2.1.259，主要新增了托管 MCP 服务器功能，允许组织通过 HTTP/SSE 为所有用户提供 MCP 服务器，配置格式与 .mcp.json 相同，但会跳过包含命令的条目。该版本还引入了 --permission-prompts none 选项，适用于无人值守的无头主机，自动拒绝所有需要提示的操作，同时保留当前权限模式（包括自动模式）的决策。此外，新增了对 GitLab MR 命令（glab mr create/merge/close/reopen/note/update）的识别，使其在工具摘要中显示为 MR \!N，并修复了并发会话相互覆盖 ~/.claude.json 更改的问题，避免工作区信任重置和 MCP/项目状态丢失。其他修复包括 Bash Read\(\) 拒绝规则覆盖更多文件操作、提示缓存失效问题、以及全屏模式空白对话等。

github · ashwin-ant · 9月2日 22:33

**「背景」** Claude Code 是 Anthropic 推出的命令行编码代理工具，支持通过 MCP（模型上下文协议）集成外部工具和数据源。MCP 服务器允许代理访问外部系统，而托管 MCP 服务器功能使组织能够集中配置这些服务器，简化部署。无头权限处理则针对 CI/CD 等无人值守环境，确保代理在无法交互时安全运行。

**「影响」** 对于使用 Claude Code 的企业和组织，托管 MCP 服务器功能简化了 MCP 服务器的集中管理，而无头权限模式则增强了在自动化环境中的安全性和可控性。并发会话修复提高了多会话工作流的可靠性，减少了状态丢失和配置重置的风险。

### [Gemini CLI v0.59.0-preview.0 发布，修复 MCP 安全漏洞](https://github.com/google-gemini/gemini-cli/releases/tag/v0.59.0-preview.0) ⭐️ 7.0/10

Google 的 Gemini CLI 发布了 v0.59.0-preview.0 版本，主要包含两项针对 MCP（模型上下文协议）相关功能的安全修复。第一项修复由 josebalius 提交，旨在防止 MCP OAuth 元数据发现和认证过程中的服务器端请求伪造（SSRF）漏洞。第二项修复由 luisfelipe-alt 提交，在受限模式下强制执行失败关闭的工作区信任机制，并过滤 mcpServers 配置。这些修复对于依赖 MCP 进行代理工具集成的后端和平台工程师尤为重要，因为它们解决了真实的安全漏洞，尽管该版本在其他方面只是常规的版本更新。

github · gemini-cli-robot · 9月1日 20:19

**「背景」** Gemini CLI 是 Google 推出的命令行 AI 编程助手，支持通过 Model Context Protocol（MCP）连接外部工具和服务器。MCP 服务器通过 OAuth 进行身份验证，并可能从配置的元数据 URL 获取信息。此前，Gemini CLI 存在安全风险：MCP 服务器 URL 未经验证，可能被利用进行服务器端请求伪造（SSRF）攻击，访问内部网络资源；同时，在受限模式下，工作区信任设置未能有效过滤 mcpServers，可能导致未受信任的服务器被连接。

**「影响」** 使用 Gemini CLI 并配置 MCP 服务器的用户和组织应立即更新至 v0.59.0-preview.0，以降低 SSRF 攻击风险，并确保在受限模式下工作区信任策略能够正确限制 MCP 服务器的访问。

### [Paint.NET 借助 Claude 完成 Direct2D 重写](https://simonwillison.net/2026/Sep/2/rick-brewster/) ⭐️ 7.0/10

Paint.NET 的创建者 Rick Brewster 宣布，该软件现在包含一个内部、从零开始、干净室逆向工程的 Direct2D 重写版本，用于在 WINE 上运行，由 AI 助手 Claude 编写，代码量约 18 万行。这一重写被封装在 PaintDotNet.Windows.Direct2D1.Managed.dll 中，并通过 /wine 参数触发，解决了 Direct2D 在 WINE 上长期无法完整支持的问题。Brewster 承认大部分代码属于“vibe coding”，即未经彻底审查，他无法审查如此庞大的代码量，并提到需要频繁监督 Claude 以确保资源管理正确，例如补充 COM 引用计数。他还称赞了 Claude 在逆向工程 Direct2D 内置效果库公式方面的出色表现，但也指出有时其设计决策不佳。这一案例展示了 AI 生成代码在复杂系统重写中的潜力与风险。

rss · Simon Willison · 9月2日 05:50

**「背景」** Direct2D 是微软的 2D 图形 API，Paint.NET 依赖它进行渲染，但 WINE 对 Direct2D 的支持一直不完整，导致 Paint.NET 无法在 Linux 上正常运行。Brewster 曾认为 Direct2D 是最大的障碍，且无法简单禁用，因此决定通过 AI 辅助进行干净室逆向工程重写，以绕过 WINE 的限制。

**「影响」** 这一重写可能使 Paint.NET 在 WINE 上获得实验性支持，为 Linux 用户提供新的使用途径，同时展示了 AI 在大型代码生成中的实际能力，但也凸显了代码审查的挑战，可能影响开发者对 AI 生成代码的信任和使用方式。

### [Codex 桌面应用捆绑 1.7GB 运行时，含 LibreOffice](https://simonwillison.net/2026/Sep/1/codex-libreoffice/) ⭐️ 7.0/10

Simon Willison 发现 OpenAI Codex 桌面应用（现已更名为 ChatGPT）在 ~/.cache/codex-runtimes/codex-primary-runtime 目录下捆绑了约 1.7GB 的运行时环境，其中包括完整的 Python 和 Node.js 安装，以及 Poppler、git 和 LibreOffice 的原生二进制文件。该运行时通过插件机制提供技能，指导 Codex 使用这些工具。这一发现揭示了 Codex 的本地执行架构，对磁盘占用、安全性和离线能力有实际影响。
